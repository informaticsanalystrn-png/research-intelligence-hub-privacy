2. Information handled by the current PDF screening prototype

The current CDB Manual Screening Prototype (versions 0.2 and 0.3) is a command-line Python tool. The operator selects a PDF file and runs the tool in a Python environment. Depending on the options selected, the tool may read and process:

  • The selected PDF's embedded text and document metadata.
  • Page counts, page-level text coverage, annotations, image-placement information, image dimensions, and PDF image references.
  • OCR text from selected pages or embedded images when optional OCR features are enabled.
  • Image fingerprints or average-hash values used to identify possible repeated visual assets.
  • Text matches, short surrounding text contexts, page locations, rule categories, confidence labels, and screening dispositions.
  • A SHA-256 fingerprint of the selected source PDF.

The tool writes JSON and/or Markdown screening reports to file paths selected by the operator. Those reports can contain excerpts and context from the PDF, page references, metadata, image-analysis details, and findings. The operator is responsible for choosing an appropriate location for the source PDF and generated reports.

The prototype is a screening aid, not legal advice, a HIPAA compliance tool, or authorization to use, store, upload, or share source material. It does not determine whether a manual or its contents may lawfully be processed or disclosed. Do not use it with patient-level information, protected health information (PHI), credentials, or confidential material unless the applicable organization and governing agreements expressly authorize that processing environment.

3. Where current processing and storage occur

The PDF screening prototype is designed to run locally in the Python environment where the operator launches it. It reads the selected PDF and writes report files to the operator-selected output location. The current prototype does not include a RIH-operated server, hosted database, user account service, or automatic upload of selected PDFs or generated reports.

The operator controls the computer, folders, and storage locations used for local runs. If the operator chooses a folder synchronized by OneDrive or another storage provider, that provider may store or process files under its own terms and settings. That synchronization is controlled by the operator and is not a built-in upload feature of the screening prototype.

The private RIH GitHub repository contains project source code, documentation, tests, and sanitized pilot-summary material. The source CDB manual and its full extracted text are not included in the repository. The public policy website contains the public project homepage and this privacy notice; it is not a storage location for research source files or Pinterest-derived information.

4. GitHub and automated tests

The repository uses GitHub for source-code hosting and version control. A GitHub Actions workflow runs regression tests when relevant prototype files are changed or when the workflow is manually run. The workflow checks out the code, installs test dependencies, and runs tests using synthetic PDF fixtures created by the tests.

The current workflow does not collect Pinterest information and does not upload the operator's selected PDF, screening report, or extracted source text as a workflow artifact. GitHub processes repository information, workflow information, and technical logs as part of providing its services under its own terms and privacy practices. RIH does not control GitHub's infrastructure-level retention or security practices.

Do not commit source manuals, extracted source text, patient data, PHI, credentials, access tokens, or confidential material to GitHub. The private repository is not a substitute for an organization-approved records repository.

5. Pinterest integration — planned, not active

A future Pinterest connector is being designed to use Pinterest's official API and user authorization, subject to Pinterest approval and its applicable developer terms. The proposed initial permissions are read-only and limited to account information, boards, and Pins that the authorized account can access. Secret/private board and Pin scopes are not part of the initial proposed scope.

If implemented, the connector may need to process the Pinterest account identifier and basic account information, authorized board identifiers and metadata, Pin identifiers and metadata, descriptions, source or destination links, timestamps, media metadata, and OAuth credentials needed for the authorized connection. The intended purpose is to organize the account owner's authorized research references, preserve source links and available attribution, support indexing and deduplication, and make those records searchable by the account owner.

These are planned functions and categories, not current collection practices. The connector, callback, token storage, hosting, logs, backups, deletion workflow, and any external processing have not yet been implemented and verified. RIH will not represent them as active or begin production processing until the implementation and this notice have been updated and reviewed.

The planned connector will not ask users to provide their Pinterest password, session cookie, or one-time login code. It will use Pinterest's official authorization flow if and when implemented.

6. AI and third-party processing

The current PDF screening prototype uses local text extraction and optional local OCR libraries. It does not call an external AI model or submit the selected PDF or screening report to an external AI provider.

The broader RIH project may later include AI-assisted research features. No Pinterest-derived information or confidential source material will be sent to an external AI provider as part of the current Pinterest integration because that integration does not exist. Before any future external processing is enabled, RIH will review the relevant provider, data categories, permissions, contractual requirements, and platform rules, and will update this notice where needed.

The current screening prototype does not include a feature that publishes selected PDFs or generated screening reports to other users or to a public research library. The operator may independently choose to share files or reports; the operator must first confirm that sharing is permitted by applicable agreements, organizational policy, and law.

RIH does not sell personal information or operate an advertising or data-broker service. No Pinterest API information is currently collected or shared because the Pinterest integration is not active.

8. Retention and deletion

The current prototype does not maintain a central RIH database or server-side copy of selected PDFs or screening reports. Source files and output reports remain in the locations chosen by the operator until the operator deletes or moves them. The operator is responsible for deletion from local devices, synchronized folders, recycle bins, and any backups or other copies under the operator's control. Retention by a separate storage provider is governed by that provider's settings and policies.

GitHub retains repository history, workflow records, and logs under its own service policies and settings. RIH cannot promise deletion from GitHub infrastructure or backups on a schedule controlled by RIH. Do not place sensitive source material or secrets in GitHub.

Because Pinterest integration is not active, there are no Pinterest-derived records or Pinterest OAuth tokens held by RIH to delete at this time. Before the integration is activated, RIH will implement and document a process for disconnecting authorization, deleting stored Pinterest-derived records and credentials under its control, handling backups, and responding to deletion requests.

9. Security

Current safeguards include keeping the source repository private, excluding source manuals and sensitive data from repository commits, using synthetic fixtures for automated tests, and documenting restrictions against committing credentials, tokens, patient data, PHI, or confidential source material.

The local prototype does not provide centralized access management, encryption-at-rest management, a hosted secrets vault, or a server-side security boundary. Security of the computer, local storage, synchronization provider, and backup configuration is the responsibility of the operator and the relevant providers.

The planned Pinterest connector will require additional controls before use, including secure handling of application secrets and OAuth tokens, authorization-state validation, access restrictions, log redaction, token refresh/revocation handling, and tested deletion procedures. These controls are not represented as implemented today.

No method of storage or transmission is completely secure. The project cannot guarantee absolute security.
